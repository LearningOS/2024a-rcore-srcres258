# 问答作业

1. 请列举 SV39 页表页表项的组成，描述其中的标志位有何作用？

    **答：** 在 RISC-V 架构中，SV39 是一种用于虚拟地址转换的页表结构。SV39 的页表项（Page Table Entry, PTE）为 64 位，其中包含了物理页号、标志位等重要信息。具体组成如下：

    ## SV39 页表项结构
    一个 SV39 页表项由以下几个字段组成：

    | 字段       | 位数 | 作用                                 |
    |------------|------|--------------------------------------|
    | PPN[2:0]   | 44   | 物理页号（Physical Page Number），指向物理内存的实际地址 |
    | RSW        | 2    | 保留位（Reserved for Supervisor），可以用于软件定义的标志位 |
    | D          | 1    | 脏位（Dirty），表示该页是否被写入过 |
    | A          | 1    | 访问位（Accessed），表示该页是否被访问过 |
    | G          | 1    | 全局位（Global），全局页的标志位，跨 ASID 的页表有效 |
    | U          | 1    | 用户位（User），指示该页是否允许用户模式访问 |
    | X          | 1    | 可执行位（Execute），指示该页是否可执行 |
    | W          | 1    | 可写位（Write），指示该页是否可写 |
    | R          | 1    | 可读位（Read），指示该页是否可读 |
    | V          | 1    | 有效位（Valid），指示该页表项是否有效 |

    ## 各标志位作用
    1. **V（Valid）**：指示页表项是否有效。无效的页表项在地址转换中会引发页面故障。
    2. **R（Read）**：指示该页是否可读。
    3. **W（Write）**：指示该页是否可写。
    4. **X（Execute）**：指示该页是否可执行。
    5. **U（User）**：指示是否允许用户模式访问该页。
    6. **G（Global）**：指示该页是否为全局页，全局页在所有地址空间标识（ASID）中均有效。
    7. **A（Accessed）**：在该页被访问时置位，用于跟踪页的访问情况，可用于页面回收机制。
    8. **D（Dirty）**：在该页被写入时置位，用于标记页是否被修改过，可用于页面回收时判断是否需要回写。

    这些标志位共同用于管理和保护内存页的访问权限、有效性和修改状态，在内存管理单元（MMU）进行虚拟地址到物理地址的转换时，确保内存的访问安全和有效性。

2. 缺页

    缺页指的是进程访问页面时页面不在页表中或在页表中无效的现象，此时 MMU 将会返回一个中断， 告知 os 进程内存访问出了问题。os 选择填补页表并重新执行异常指令或者杀死进程。

    - 请问哪些异常可能是缺页导致的？

        **答：** 缺页现象会引发几种典型的异常，主要包括以下几类：

        1. **缺页异常（Page Fault）**  
        
            这是最常见的缺页引发的异常。当进程访问的页面不在物理内存中（即页表项无效或者对应页面未加载到内存中），MMU 会触发缺页异常。这种情况下，操作系统可以通过将所需页面从磁盘加载到内存，更新页表，再继续执行进程。  
        
        2. **权限异常（Permission Fault）**  
        
            缺页还可能导致权限异常。若页面存在于内存中，但进程请求的访问类型（如读、写或执行）不符合页表中记录的权限（例如请求写访问但页面不可写），则会触发权限异常。这种权限错误也是通过页表检查发现的，操作系统可能会选择终止该进程。

        3. **地址空间异常（Address Space Fault）**  
        
            当进程访问的地址超出它的有效地址空间范围时（例如访问未分配的虚拟地址区域），这通常也被认为是一种缺页异常。在这种情况下，操作系统可能会选择分配所需的页面（如按需分页）或直接终止进程。

            在 RISC-V 和其他大部分现代处理器架构中，MMU 对虚拟内存的管理依赖于页表项的有效性和权限标志位，因此当进程试图访问无效页或未授权的内存时，就会引发相应的缺页或权限异常。这类异常通过操作系统的异常处理机制来解决，具体处理方式依赖于系统设计以及页面的使用场景。
    
    - 发生缺页时，描述相关重要寄存器的值，上次实验描述过的可以简略。

        **答：** 当 RISC-V 处理器发生缺页异常时，`stval` 保存导致异常的虚拟地址，`scause` 标识缺页的类型，`sepc` 保存异常指令地址。操作系统利用这些寄存器的值查找缺页原因、进行页面分配或权限调整，从而有效处理缺页并恢复进程执行。
    
    缺页有两个常见的原因，其一是 Lazy 策略，也就是直到内存页面被访问才实际进行页表操作。 比如，一个程序被执行时，进程的代码段理论上需要从磁盘加载到内存。但是 os 并不会马上这样做， 而是会保存 .text 段在磁盘的位置信息，在这些代码第一次被执行时才完成从磁盘的加载操作。

    - 这样做有哪些好处？

        **答：** 采用 Lazy 策略（延迟加载）进行缺页处理，即在页面被访问时才实际进行内存分配和页面加载，有以下几方面的好处：

        1. **减少不必要的页面加载**  

        程序执行时，实际访问的代码和数据往往远少于其所有页面。延迟加载仅在页面被实际访问时才加载，避免了未被使用的页面加载，从而节省了内存和磁盘 I/O 开销。

        2. **加速程序启动**  

        延迟加载可以大幅缩短程序启动时间。系统不必在程序启动时将所有页面加载到内存，而是可以尽快进入执行阶段。这使得大型程序尤其受益，因为在启动时只加载了必要的启动页面，减少了初始化时间。

        3. **内存资源优化**  

        延迟加载可以优化内存的整体利用率。因为系统不必立即分配所有页面的内存，所以内存资源可以优先用于其他运行的进程和任务，尤其在内存资源紧张的情况下，这种方法可以避免不必要的内存占用。

        4. **便于错误管理**  

        延迟加载还便于页面和数据的动态管理。对于不再使用的页面，操作系统可以随时将它们移出内存而不担心提前加载。这样可以更方便地实现页面置换算法，从而提高内存管理的灵活性和效率。

        5. **按需分配的灵活性**  

        Lazy 策略还便于系统在加载页面时进行额外的检查或优化。例如，系统可以在加载页面时考虑内存碎片问题、页表优化等，这些工作可以更合理地安排在页面加载时完成，而不必在程序启动时一并完成。

        因此，Lazy 策略能够以更灵活的方式调度内存资源，提高启动效率和内存利用率，有助于实现更高效的内存管理。
    
    其实，我们的 mmap 也可以采取 Lazy 策略，比如：一个用户进程先后申请了 10G 的内存空间， 然后用了其中 1M 就直接退出了。按照现在的做法，我们显然亏大了，进行了很多没有意义的页表操作。

        **答：** 映射 10 GB 连续虚拟地址的 SV39 页表总内存开销约为 16 MB。
    
    - 请简单思考如何才能实现 Lazy 策略，缺页时又如何处理？描述合理即可，不需要考虑实现。

        **答：** 为了实现 Lazy 策略，可以采取以下步骤和策略：

        1. **延迟页表分配**  
        当用户进程申请内存（例如通过 `mmap`）时，操作系统仅记录分配的虚拟地址空间范围，但不立即分配物理页面或建立完整的页表项。这一方法可以通过在页表中标记该范围为“暂未分配”状态来实现。

        2. **初始化虚拟映射记录**  
        操作系统在内部记录分配的虚拟地址区间和相应的懒加载标记，方便在后续实际访问时触发分配逻辑。这样，申请的虚拟地址空间不会立即映射到物理页面，从而避免不必要的内存分配和页表操作。

        ## 缺页时的处理步骤

        当进程首次访问这些延迟分配的页面时，由于页表项未建立，MMU 会触发缺页异常。此时操作系统可以按以下步骤处理：

        1. **捕获缺页异常**  
        操作系统捕获缺页异常，检查 `stval` 寄存器中的地址，确认缺页是由于 Lazy 分配导致的，而非非法访问。

        2. **分配物理页面**  
        操作系统在物理内存中分配实际的物理页面，并初始化页面内容（例如填充为零，若是匿名映射）。

        3. **更新页表项**  
        操作系统将新的物理页面地址填入相应的页表项，并设置必要的权限标志（如读、写、执行）。

        4. **恢复进程执行**  
        处理完成后，操作系统返回缺页处理并恢复进程，从而重新执行引发缺页的指令。
    
    缺页的另一个常见原因是 swap 策略，也就是内存页面可能被换到磁盘上了，导致对应页面失效。

    - 此时页面失效如何表现在页表项(PTE)上？

        **答：** 当页面被换出到磁盘上时，PTE 中的有效位 V 被清零，标识页面无效；操作系统可能会在其他标志位或 PPN 字段中存放 swap 相关信息，以便在缺页时重新加载页面。这种表示方式能确保在页面重新加载后，进程能够继续正确执行。

3. 双页表与单页表

    为了防范侧信道攻击，我们的 os 使用了双页表。但是传统的设计一直是单页表的，也就是说， 用户线程和对应的内核线程共用同一张页表，只不过内核对应的地址只允许在内核态访问。 (备注：这里的单/双的说法仅为自创的通俗说法，并无这个名词概念，详情见 [KPTI](https://en.wikipedia.org/wiki/Kernel_page-table_isolation) )

    - 在单页表情况下，如何更换页表？

        **答：** ChatGPT

        在单页表的情况下，更换页表通常涉及更新用于地址转换的根页表指针，使其指向新的页表根地址。以下是具体步骤：

        1. **切换页表根地址**
        
        RISC-V 和许多其他架构的操作系统会通过更新页表根寄存器（如 `satp` 寄存器）来更换页表。具体做法是将新的页表根物理地址写入寄存器。例如，在 RISC-V 中，`satp` 寄存器的 PPN（Physical Page Number）字段用于存储根页表的物理地址。

        2. **刷新 TLB**
        
        由于更换了页表，之前在 TLB（Translation Lookaside Buffer）中缓存的虚拟地址与物理地址的映射可能已不再有效。因此，更换页表后必须刷新 TLB，以确保后续内存访问会根据新页表进行转换。不同架构提供了不同的 TLB 刷新指令。例如在 RISC-V 中，可以通过 `sfence.vma` 指令刷新 TLB。

        3. **切换上下文**
        
        一般情况下，更换页表发生在上下文切换时，以便在用户进程之间或在用户态和内核态之间切换。操作系统会通过更新页表指针并刷新 TLB 来确保新的上下文中的虚拟地址映射准确无误。

    - 单页表情况下，如何控制用户态无法访问内核页面？（tips:看看上一题最后一问）

        **答：** 在单页表的情况下，控制用户态无法访问内核页面主要通过以下两种方法来实现：

        1. **权限位控制**  

        页表项中的权限位（例如 RISC-V 中的 `U` 位）用于区分用户态和内核态的访问权限。对于内核页面，操作系统会在页表项中将 `U` 位清零，表示只有内核态才有权限访问这些页面。当用户态代码尝试访问 `U` 位清零的页面时，硬件会触发权限异常（通常称为“访问控制异常”），阻止访问。

        2. **地址空间分割**  

        操作系统通常会将虚拟地址空间划分为用户态区域和内核态区域。例如，在 64 位系统中，常见的做法是将较高的虚拟地址范围保留给内核态，较低的地址范围分配给用户态。这样，用户态的代码只能访问其地址范围内的页面，而访问内核地址范围会直接触发地址空间异常（如越界访问异常）。

    - 单页表有何优势？（回答合理即可）

        **答：** 单页表结构相比于双页表（如 KPTI）有以下几个主要优势：

        1. **降低内存占用**  

        单页表避免了为每个进程维护两套页表（用户页表和内核页表）的开销，只需一张页表即可描述整个用户态和内核态的地址空间。这节省了页表所需的内存，尤其是在多进程系统中，内存开销减少显著。

        2. **上下文切换更高效**  

        在单页表结构下，从用户态切换到内核态（或反之）不需要更换页表，也无需刷新 TLB（Translation Lookaside Buffer）。这减少了上下文切换时的开销，因为刷新 TLB 不仅耗时，还可能导致后续访问的性能下降。单页表结构使得用户态和内核态切换更快速。

        3. **简化页表管理**  

        单页表结构下，用户态和内核态共享同一张页表，管理逻辑相对简单，无需维护两套页表、同步内核页表内容。这对于内核页表和用户页表频繁共享数据的场景（如访问 I/O 缓存）尤为有利，减少了双页表间的映射和维护复杂度。

        4. **提高缓存命中率**  

        共享页表可以提高 TLB 和 CPU 缓存的命中率。因为页表条目都在同一页表中，内核和用户态的访问都可以使用相同的缓存映射，避免了在双页表结构中因频繁切换页表而导致的 TLB 失效。

    - 双页表实现下，何时需要更换页表？假设你写一个单页表操作系统，你会选择何时更换页表（回答合理即可）？

        **答：** 在双页表实现下，页表的切换通常发生在 **用户态与内核态之间的上下文切换** 或 **进程切换** 时。我们来分析双页表和单页表的区别，理解在单页表操作系统中应当如何选择更换页表的时机。

        ## 双页表的页表切换时机

        双页表的实现（如 KPTI）通常会使用两个独立的页表：一个用于用户态，一个用于内核态。切换页表的主要时机是在以下两种情况下：

        1. **从用户态切换到内核态**  

        当进程从用户态进入内核态时，系统需要更换页表。此时，操作系统会将页表的根指针（如 RISC-V 中的 `satp` 寄存器）切换到内核页表的根地址，从而使得虚拟地址转换使用内核页表，而不是用户页表。

        2. **从内核态切换回用户态**  

        当内核完成任务并准备返回用户态时，操作系统会再次更换页表，将页表根指针切换回用户页表的根地址。这样，用户进程的虚拟地址空间就会恢复有效。

        ## 单页表操作系统的页表切换时机

        对于一个 **单页表操作系统**，因为用户态和内核态共用同一张页表，所以不需要像双页表那样频繁切换不同的页表。然而，仍然有一些情况需要更换页表，主要是以下两种情况：

        1. **从用户态进入内核态时**  

        尽管用户态和内核态使用相同的页表，但为了防止用户态访问内核页，操作系统通常会通过修改权限位来控制访问。当从用户态进入内核态时，操作系统会调整页表中的权限标志（如设置 `U` 位为 0），使得用户进程无法访问内核页。这实际上是“切换”页表的某种形式，尽管物理页表没有变化，权限控制发生了变化。

        - 通过将用户进程的 `U` 位权限清除（禁用访问内核页），从而保护内核地址空间。
        - 切换回用户态时，操作系统会恢复页表中用户区域的权限，使得用户进程能够访问自己的虚拟地址空间。

        2. **进行上下文切换时**  

        如果操作系统支持多进程管理，切换到另一个进程时，虽然页表是共享的，但不同进程的虚拟地址空间需要映射到不同的物理内存区域。因此，在进程切换时，操作系统需要更新 `satp` 寄存器，使得虚拟地址到物理地址的映射指向当前进程的页表。即便使用单页表，进程之间的页表仍然是独立的。

        - 操作系统会在进程切换时通过更新页表根地址来确保新的进程访问其独立的地址空间。
        - 在单页表下，操作系统通常会通过修改页表项中的物理地址（或 `satp` 寄存器）来切换至目标进程的虚拟地址空间。

        ### 总结：单页表操作系统选择何时更换页表？

        在单页表的情况下，页表切换通常发生在以下几种情况：

        - **从用户态切换到内核态**：在用户态访问内核地址空间时，通过修改页表项的权限标志来阻止用户访问内核页，从而“切换”到内核态。这里的切换更多是权限控制，而非实际更换页表。
        
        - **从内核态切换回用户态**：操作系统会恢复页表项中的用户区权限，使得用户进程可以访问自己的虚拟地址空间。

        - **进程切换时**：在切换不同进程时，操作系统更新 `satp` 寄存器，指向当前进程的页表。尽管页表结构相同，内存映射会依据不同的进程进行更新。

        因此，单页表操作系统的页表更换主要与权限管理和进程切换相关。相比双页表，单页表系统更注重通过控制页表项中的权限位来实现地址空间隔离，而不需要实际更换两张独立的页表。
